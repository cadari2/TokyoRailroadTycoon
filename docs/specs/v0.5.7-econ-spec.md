# v0.5.7 Spec — Endogenous Economy & Randomized Macro Events

**Status:** approved for implementation (planning session 2026-07-17).
**Audience:** an implementing model/developer with ZERO conversation context. Everything needed is in this file plus the referenced source lines (line numbers as of commit `e5d9cbb`, v0.5.6).

## 0. Scope, non-goals, and the one-paragraph summary

Replace the scripted real-history macro block (`js/events.js:301-318` — fixed-year 1904/1918/1955/1964/1986/1991/2008/2020/2023 booms, busts, bubble, pandemics) with **(a)** an endogenous city-attractiveness engine that drives population/migration and the business cycle from what the player-built city actually is, damped by congestion and prices, and **(b)** a randomized hazard deck (same design grammar as the existing war/quake system) for discrete shocks — pandemics, financial panics, land bubbles — with era-conditional permanent aftermaths. Redesign occupancy fill from exponential drift to a demand-paced logistic. Everything else (causal inflation `updateInflation`, disaster damage engine, tech unlock years, taishin standards, kaidō paving, era-keyed alt modes/VoT/construction pace, AI entry windows) **stays as-is**: those are the fictional world's technological arc, not its economic history.

**Non-goals (explicitly out of scope — do not build):** per-agent households/firms, off-map trade economy simulation, changes to fare/OD assignment (`assignOD`), changes to the inflation formula itself, randomizing tech unlock years or era boundaries, multi-map interaction. The cars/buses road animation (§8) is display-only flavor.

**Hard balance rails (must survive tuning, verified via `tools/balance.js` + `tools/smoke.js`):**
1. **Opening years pinch:** Meiji start remains tight; the new occupancy/attractiveness math must not make early property income a shortcut around railroading. Property income before ~1900 should be negligible for a player who hasn't built rail.
2. **office_l stays the big gamble:** order-of-magnitude cost/upkeep, only pays where demand + the player's railway fill it.
3. **Rail-first → property-later arc is intentional** (the Tokyu/Hankyu model): fares dominate income early; by late game a well-played company's property/ekinaka share may rival or exceed fares. This should EMERGE from land-value growth + densification, not from a scripted multiplier. Add a balance-check metric, not a mechanic.

**Performance budget:** new computations run at most once per simulated day (like `demandFieldCached`, `js/sim.js:366-372`) or once per year; nothing new in the per-frame path. A yearly pass over 2,500 hexes and one O(hexes×radius) field pass per sim-day are acceptable.

**Determinism:** all new randomness draws from the existing event RNG `st.evRng` — never `Math.random()`.

**Save compatibility:** old saves MUST load (see §7). Bump `SAVE_VERSION`; seed missing state; never crash or zero out a loaded economy.

## 2. Randomized macro events — the hazard deck (HIGH RISK)

New function `deckEvents(st)` called from `yearlyEvents` (`js/events.js:269`) where the scripted block was. Each event type follows the war/quake grammar: per-year hazard chance, per-playthrough cap, refractory gap, gated by `majorAllowedSoft(st)` (`js/events.js:391`), randomized magnitude/duration, effects delivered through EXISTING channels (`startEvent` pax curves, `st.econ.cycle`, `st.econ.landBubble`, inflation pressure objects).

Add to `CFG.EVENTS` (all names below are normative — the implementer must use these keys):

```js
DECK: {
  pandemic: {
    chance: 0.009, cap: 2, gapYears: 25,
    // magnitude: paxMult drawn U(0.45, 0.7); duration U(270, 720) days; curve "hold"
    paxMultRange: [0.45, 0.7], daysRange: [270, 720],
    // era-conditional permanent aftermath (§4.3): remote work exists only when the
    // economy is office/communications-heavy — gate on calendar era, not event count
    remoteWorkFromEra: "heisei",       // eraOf(year).key ∈ {heisei, reiwa}
    remoteWorkChance: 0.6,             // given a pandemic in an eligible era
    commuteFactorRange: [0.82, 0.92],  // multiplies st.econ.commuteFactor (floor 0.7)
  },
  panic: {   // financial panic / crash (replaces scripted 1991-burst & 2008-GFC roles)
    chance: 0.02, cap: 4, gapYears: 12,
    cycleHitRange: [0.80, 0.93],   // st.econ.cycle = min(cycle, draw)
    // if a bubble is in "mania" phase, a panic ALWAYS bursts it (see bubble below)
  },
  bubble: {  // multi-year land-price mania then burst (replaces scripted 1986/1991)
    chance: 0.012, cap: 2, gapYears: 30,
    // mania phase: landBubble ramps to peak over rampYears, holds until burst roll
    peakRange: [1.7, 2.4], rampYears: [2, 4],
    burstChancePerYear: 0.22,          // once at peak; also burst on any panic event
    burstFloorRange: [0.75, 0.95],     // landBubble set here on burst; cycle ×0.92
  },
  // NOTE: booms/recessions are NOT deck events — they emerge from the endogenous
  // cycle (§5.4). The deck only handles discrete named calamities/manias.
},
```

Implementation notes:
- Bubble mania phase overrides the mean-reversion pull on `landBubble` (`events.js:386`) while active (skip the reversion line when `deck.bubble.phase === "mania"`).
- Pandemic uses `startEvent` with `curve: "hold"` exactly like the old scripted ones; log text must be era-appropriate but generic ("Influenza pandemic" pre-1950, "Pandemic" after — pick by calendar era, cosmetic only).
- All draws via `rnd(st.evRng)` / `rndInt(st.evRng, …)`.
- **Worth arguing about — event frequency:** these rates give a median playthrough ~1 pandemic, ~2 panics, ~1 bubble in 156 years. Recommendation: ship these numbers, expose them all in `CFG.EVENTS.DECK`, and validate with the Monte-Carlo harness (§9). Do not add "guaranteed at least one" logic — the war/quake precedent (some games see none) is the established house style.

## 3. Occupancy: logistic fill redesign (HIGH RISK — touches money flow)

Replaces the drift in `updateOccupancy` (`js/sim.js:510-525`) and the flat start at `js/world.js:1378`.

### 3.1 Opening occupancy (pre-leasing)
A completed development opens at demand-dependent occupancy instead of flat 0.15:
```js
h.occ = clamp(0.05 + 0.45 * occupancyTarget(st, idx), OCC.min, 0.5);
```
A building in a starving district opens ~40–50% pre-leased; in a dead one ~6–8%. Same rule for parcels bought with sitting tenants is NOT used — those keep the existing seed `h.occ = occupancyTarget(...)` (`js/world.js:275`, unchanged).

### 3.2 Monthly update (logistic up, linear down)
Per rentable parcel, each simulated month (same call site as today):
```js
const T = occupancyTarget(st, i);                    // §3.3
if (h.occ < T) {
  // logistic lease-up, paced by how hungry the district is:
  // rate r = OCC.fillBase * (0.5 + demandPressure), demandPressure = sqrt(field/max) (0..1)
  const r = OCC.fillBase * (0.5 + dp);
  h.occ = Math.min(T, h.occ + r * h.occ * (1 - h.occ / T));
} else {
  // vacancies open linearly — tenants leave at a steady clip, no S-curve down
  h.occ = Math.max(T, h.occ + (T - h.occ) * OCC.vacateDrift);
}
```
New `CFG.LAND.OCC` fields: `fillBase: 0.35`, `vacateDrift: 0.18`. Remove `drift` and `newBuildStart` (grep for both; `newBuildStart` is also referenced in UI copy `js/ui.js:2289` — rewrite that sentence to describe demand-dependent opening).
Floor guard: because logistic growth stalls at occ≈0, clamp `h.occ` to `max(h.occ, OCC.min)` (min stays 0.03) BEFORE the logistic step so recovery from a dead district is possible.

### 3.3 `occupancyTarget` re-sourcing
Keep the function shape (`js/world.js:305-336`) — demand × access × supply competition — but replace the hand-tuned `trend` blends (`js/world.js:333`) with the attractiveness components:
```js
const A = st.econ.attract;
const trend = residential
  ? (0.6 + 0.4 * st.econ.popPressure) * A.afford        // homes: population tide, priced out by cost
  : (0.7 + 0.3 * (st.econ.cycle || 1)) * (0.8 + 0.2 * A.jobs);  // commerce/offices: cycle + job market
// offices additionally: target *= st.econ.commuteFactor (remote work empties offices, permanently)
```
Offices multiply by `commuteFactor`; residential does not (people still live there — this is the mechanism that makes a late-era pandemic reshape the office market specifically).

**Worth arguing about — quote honesty:** `estimatedRentYear` (`js/world.js:1335-1339`) defaults to 100% occupancy in build quotes while actual rent follows real occupancy. Recommendation: build-quote UI (`js/ui.js:2274-2289` area) must show BOTH "at projected opening occupancy" and "ceiling at full occupancy". Low code risk, high trust payoff.

## 4. Shock → economy wiring (MEDIUM RISK, mostly existing channels)

| Shock | Demand (pax) | Population | Prices/inflation | Permanent aftermath |
|---|---|---|---|---|
| War (existing) | `warPaxHit`×intensity | `POP.warWeight` | `INFLATION.warWeight` + postwar | razed hexes (existing) — keep |
| Major quake (existing) | slow-curve event | `POP.quakeWeight` via rebuild | `rebuildWeight` | none — keep |
| Pandemic (deck) | hold-curve paxMult | NEW: while active, popRate −0.5×(1−paxMult) (flight + mortality, abstracted) | none | era-gated remote work: `commuteFactor ×= draw` (§2) |
| Panic (deck) | via cycle (cycle already scales demand & occupancy) | via cycle term in popRate (existing) | via `cycleWeight` (deflationary — existing formula) | none |
| Bubble (deck) | none direct | mania mildly boosts cycle (+0.05 while mania) | landBubble inflates land values → rents, taxes, buyout prices (all existing consumers) | burst can strand overpaid land — emergent, no code |

Rule: **no new economy channels** — every shock effect must flow through `st.econ.{cycle, paxMult, landBubble, popPressure, commuteFactor}` or the inflation pressure objects (`st.econ.postwar`, `st.econ.rebuild`). If an effect can't be expressed through those, escalate rather than invent a channel.

## 5. Endogenous population & the business cycle (HIGH RISK — replaces scripted history)

### 5.1 Principle
The map is one node in an implied wider world with unlimited migrants and capital. Net flow in/out is set by the city's **attractiveness** A relative to neutral (1.0). Damping is economic: growth raises land prices and train crowding, which lower A (bid-rent logic). Hard clamps (`POP.min/max` on pressure) remain as safety rails.

### 5.2 `updateAttractiveness(st)` — new, called yearly from `onNewYear` before `updatePopulation`
All inputs already exist or are cheap yearly aggregates:
```js
// transit: how much of the developed city has real rail service, and how good
//   coverage = share of hexes with dev>0 that lie within STATION.catchment of an
//              operating station (single map pass, yearly)
//   service  = min(1, st.econ.demandIndex / 4)   (existing saturating index)
//   crowding = mean line load across all companies' lines (already computed for HR overwork)
transit = (0.4 + 0.6 * coverage) * (0.6 + 0.4 * service);
congestion = clamp(1.15 - 0.35 * max(0, meanLoad - 0.85), 0.6, 1); // penalty kicks in past 85% load
// housing: is there somewhere affordable to live?
//   resVacancy = 1 − mean occ over residential rentable parcels (some slack = good; none = shortage)
//   afford     = clamp(refRent / actualMeanResRentPerParcel, 0.5, 1.2)
//                refRent = a CFG anchor × inflation (so pure inflation is neutral —
//                only REAL rent growth above inflation penalizes)
housing = (0.7 + 0.6 * clamp(resVacancy / 0.15, 0, 1)) * afford;   // ~5–15% vacancy is healthy
// jobs: office/commerce floorspace actually reachable — sum of att over hexes within
//   catchment of any operating station, normalized by a CFG anchor per era? NO —
//   normalize by total map att (share reachable), era-free:
jobs = 0.5 + 1.0 * reachableAttShare;
overall = clamp(transit * housing * jobs, 0.3, 2.0) * congestion;
st.econ.attract = { transit, housing, jobs, congestion, afford, overall };
```
Exact coefficients go in a new `CFG.ATTRACT` block — every literal above must be a named CFG field. These are starting values; the Monte-Carlo harness (§9) tunes them.

### 5.3 `updatePopulation` rewrite (`js/main.js:122-131`)
```js
let rate = P.baseRate                       // NEW CFG.POP.baseRate: 0.004 (a mildly growing world)
         + P.attractWeight * (e.attract.overall - 1);   // NEW attractWeight: 0.018
rate += P.cycleWeight * ((e.cycle||1) - 1);              // existing
if (st.war?.active) rate += P.warWeight * st.war.inten;  // existing
if (e.rebuild?.years > 0) rate += P.quakeWeight * e.rebuild.k;  // existing
if (activePandemic) rate += pandemicPopHit;              // §4
// DELETE the railWeight term — rail's pull now lives inside attract.transit (do not double-count)
e.popRate = rate;
e.popPressure = clamp(1 + P.pressureK * rate, P.min, P.max);
```
Consumers of `popPressure` (growth engine, occupancy targets) are unchanged.
**Consequence to accept knowingly:** there is no scripted Heisei stagnation / Reiwa decline anymore. A well-run city can still be booming in 2020; a bad one can empty out in 1950. That is the design intent (interview decision). Late-game texture (aging/decline) may return later as a deck event — out of scope for 0.5.7.

### 5.4 The business cycle becomes endogenous-ish
Keep the mean-reverting drift (`events.js:385`) as the base. Add one coupling term so booms follow real city growth: yearly, `cycle += CFG.ECON.growthCoupling * (popRate - baseRate)` (suggested 0.5, clamped by existing bounds). Deck panics/bubbles shove it per §2. Delete nothing else.

### 5.5 Feedback-loop stability requirement
The loop attract→pop→dev→rent/crowding→attract must be verified stable: the §9 harness runs 200 seeded 156-year AI-only games and asserts (a) total population stays within [0.5×, 6×] of its 1872 value in ≥95% of runs, (b) no NaN/Infinity in econ fields ever, (c) `popPressure` spends <10% of years pinned at a clamp. Failing any of these is a tuning bug, not a shipping variance.

## Appendix B — Decisions flagged "worth arguing about" (with recommendations, all approved in interview)
1. Deck vs. oscillator for shocks → **deck** (house style, proven by war/quake).
2. Scripted vs. endogenous population → **endogenous attractiveness**, congestion+price damped; scripted era decline deleted knowingly.
3. Shock permanence → **era-conditional** (remote work only Heisei+).
4. Occupancy → **full logistic redesign** incl. demand-dependent opening (user chose over minimal re-sourcing).
5. Balance rails → opening pinch, office_l gamble, rail-first→property-later arc preserved.
6. Perf/saves (defaults, not explicitly confirmed) → per-sim-day budget; **saves migrate, never break**.
